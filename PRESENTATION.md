## Likely questions and short answers

| Question | Answer |
|---|---|
| Why `src`/`tests`/`docs`? | It separates shipping code from verification and documentation, so a new contributor knows where to look without reading anything first. |
| Why a `.gitignore` before writing code? | It prevents `__pycache__`, virtual environments and editor files from entering history, which is hard to undo later. |
| Why GitHub Pages and not a paid host? | It deploys directly from the repository I already maintain, costs nothing, and supports HTTPS on the default domain. |
| Why Track D? | Cloud and automation work is where my Linux and scripting interest converts into a role; the roadmap sequences Docker and AWS to reach it. |
| Can the unit test run? | The test is written with `unittest`; the command is `python -m unittest discover -s tests -v`. It requires Python installed locally. |
| What is missing? | The HackerRank Python Basic certificate is still in progress, and repository pinning plus the LinkedIn website field are browser-side steps. |
